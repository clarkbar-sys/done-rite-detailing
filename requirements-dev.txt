# Python tooling for GDScript format/lint (`make format` / `make lint`).
# Installed into a throwaway venv at .venv-lint/ — never system-wide. Same
# philosophy as the Godot pin in scripts/fetch-godot.sh: reproducible, not
# ambient "whatever pip resolves today".
#
# gdtoolkit is the pin that matters (a floating linter means CI can start
# failing with no commit to blame); everything below it is `pip freeze`
# output for that exact version, so the whole dependency graph — not just
# the top-level package — is locked to one set of versions.
#
# No --hash pins here on purpose: PyYAML and regex ship per-platform,
# per-CPython-version compiled wheels (verified with `pip download`), so
# hash-pinning would tie this file to one wheel and break `pip install` on
# any other platform or Python minor version — worse than the drift it
# would prevent. Exact-version pinning already gives the "no surprise
# upgrades" guarantee; CI installs with the same Python version the venv
# recipe below targets (see .github/workflows/ci-godot.yml).
#
# To bump gdtoolkit: change the version below, then inside a fresh venv run
#   pip install gdtoolkit==<new version> && pip freeze
# and paste the full result back in here. Re-run `make lint` before pushing —
# a gdtoolkit bump can change formatting/lint output same as a Godot bump can
# change compiler warnings.
